# An x86-only fast path is invisible on ARM64, and two forks have one

**Goal: read `rpcsx/docs/arm64/aes.md` — "the hardware is there and the emulator
never asks for it" — and check whether the class is fleet-wide.**

**It is not fleet-wide, and it is not unique either. Two forks, two subsystems,
and the second one is on a path this project calls flagship.**

## The class

**A fast path guarded on an x86 macro compiles to nothing on ARM64, and nothing
warns.** The fallback is correct, so there is no bug, no crash and no test
failure — **only the reference implementation, silently.**

## Instance 1: rpcsx does every AES operation in software

`Crypto/aesni.cpp` opens with `#if defined(__SSE2__) || defined(_M_X64)` and
**that guard wraps the whole file.** Every dispatch point in `Crypto/aes.cpp`
carries the same guard:

| Line | Guarded call | ARM64 result |
| --- | --- | --- |
| 462 | `aesni_setkey_enc` | software key schedule |
| 567 | `aesni_inverse_key` | software inverse key |
| 666 | `aesni_crypt_ecb` | **software block encrypt and decrypt** |

**What runs instead is the four-table PolarSSL implementation** — sixteen table
lookups and a pile of XORs per round, ten to fourteen rounds per block.

**The device reports `aes pmull sha1 sha2 sha3 sha512`. None of it is reachable
from this path.**

**Two costs, not one**, and the second is the interesting one:

- **Throughput.** ARMv8 does a round in `AESE` + `AESMC` against sixteen
  dependent loads and XORs.
- **Cache.** The software path **streams 8 KB of lookup tables through L1** on a
  machine where other threads need it.

**And it is on the boot path** — SELF and SPRX decryption for **every module**,
with one title's cache build walking **1,187** of them.

## Instance 2: ARMSX2's BC7 texture decompressor, and it is worse placed

`common/TextureDecompress.cpp:473`:

```c
#if (defined(_M_AMD64) || defined(__x86_64__) || defined(__SSE2__))
#  define BC7DECOMP_USE_SSE2
#endif
```

**Searched the whole file for `ARM`, `NEON`, `aarch64` and `__arm`: zero
matches.** The SSE2 path builds `__m128i` weight tables and uses
`<immintrin.h>`; **on the Thor none of it compiles and BC7 blocks decode
scalar.**

**Why the placement matters.** BC7 is a texture compression format, and **this
project's flagship features are HD texture packs and per-class texture
routing.** A BC7-compressed replacement texture decodes on the scalar path.

**Bound the claim honestly: this is load-time work, not per-frame.** It costs
texture load and pack install, not frame time — **which is exactly the "work that
happens once" this project prefers**, only slower than it needs to be.

## The rest of the fleet is clean, and the near-misses are instructive

Searched every fork's own source for `defined(__SSE2__)`, `defined(__AES__)` and
`defined(_M_X64)`, vendored trees excluded:

| Fork | Files | Verdict on reading |
| --- | --- | --- |
| **rpcsx** | 11 | **instance 1** |
| Cemu | 2 | `precompiled.h` includes x86 intrinsics; `fast_float.h` **handles `_M_ARM64`** |
| Vita3K | 2 | `miniz.h` is vendored; **`spin_wait.h` has an explicit ARM64 branch** |
| eden | 1 | `uint128.h` tests **`_M_X64 || _M_ARM64`** — correct |
| **ARMSX2** | 1 | **instance 2** |
| azahar, xenia | 0 | — |

**Three of the near-misses are correct code**, and they are correct in the same
way: **the guard names ARM64 beside x86.** That is the shape to look for when
auditing — **an x86 macro with no ARM sibling in the same condition.**

## What to do

- **Add the class to `tools/bug_class_sweep.py`** with the search that found it,
  so it is re-runnable rather than a one-off read.
- **ARMSX2's BC7 path is a propagation candidate with no source to copy from** —
  nobody in the fleet has an ARM BC7 decoder. **It is a write, not a port**, so it
  needs a measurement first: how much BC7 does a texture pack actually contain?
- **Neither is a frame-time claim.** rpcsx's is boot and install time; ARMSX2's is
  texture load. **Both are the kind of cost this project has decided it cares
  about** — Foundation point 4 counts the time a person waits.

## Limits

- **Nothing measured.** No AES throughput number, no BC7 decode time, on either
  fork.
- **rpcsx's instance is read from its own document**, not reproduced.
- **The fleet search covers `__SSE2__`, `__AES__` and `_M_X64` only.** A fast path
  guarded on `__AVX2__`, `__BMI__` or a runtime x86 dispatch would not appear.
  **This is one vocabulary and the rule about that is well established here.**
- **Whether PS2 texture packs actually use BC7 was not checked**, and it decides
  whether instance 2 matters at all.
